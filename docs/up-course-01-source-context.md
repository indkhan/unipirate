# UP-COURSE-01 bounded source context

This source-only change shares deterministic URL priority between retrieval selection
and model context selection. Captured official application/requirements/regulations
and FAQ links rank before generic PDFs. Observed link labels and URL host/path guide
priority; neither priority nor a PDF extension establishes course authority.

Context keeps the existing retrieved DAAD identity/domain and captured link-chain
boundary. Availability/effective warnings, specific programme identity, concrete
language lists/exceptions and fee statements precede broad application prose and
university marketing. Each excerpt is a contiguous literal slice of one paragraph;
long paragraphs can yield separate slices, never a combined evidence quote.
Recognized availability/effective-warning paragraphs are emitted only in full:
when one exceeds the remaining 4,000-character source budget, the whole paragraph
is omitted, including its assertions and warning. Raw captures and omission counts
retain that gap for manual review; a warning is never clipped to fit the budget.

The limits remain four sources, 4,000 characters per source, 16,000 total,
2,000 per excerpt and 20,000 per raw capture. Counts disclose omissions and the
I/O shell retains its existing unresolved/manual-review warnings. Full observations
remain intact for admin review. Heuristic selection cannot ensure every topic fits.

Saved smoke-10 public captures now retain the literal 2026 requirements / future
2027 publication warning and later language appendix. This supplies no published
2027 requirement, applicant scope or course-authoritative scope to the FAQ. Source,
quote, value, identity, degree, intake/applicant, conflict and review gates are
unchanged. Navigation already consuming a raw 20k capture cannot be repaired by
this selection; the missing fee body stays unresolved for manual review.

Original Lightning model, provider, prompt instructions, output schema and runtime
caps are unchanged. Offline regression/replay does not establish operational AI
success or explain smoke 10's zero facts: raw submitted tool arguments were not
retained. Root still owns review, integration documentation and DB/service gates.
Any new provider smoke requires separately explicit one-call approval; the previous
single authorization is consumed and the alternative model is not adopted.

Actual-14 follow-up: paragraph completeness now applies to every paragraph, not
only recognized availability warnings. A paragraph that exceeds the remaining
source budget is omitted in full. Original captures, literal formatting, identity,
scope and review gates remain unchanged. The saved actual-14 submission still
fails strict grounding; native SDK replay is offline evidence, not provider acceptance.
